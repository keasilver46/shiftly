# 0003. 스타일링은 CSS Modules + CSS 변수 토큰

- 날짜: 2026-10-02
- 상태: 채택

## 배경

프론트엔드 첫 화면(로그인)을 만들면서 스타일링 방식을 정해야 했다.
이후 모든 화면이 같은 방식을 따르게 되므로 처음에 결정해야 바꾸는 비용이 적다.

요구 조건은 다음과 같았다.

- 디자인 토큰(색 5개, 서체 1종, 크기 5단계, 모서리 2종)을 한 곳에서 관리하고 모든 화면이 그 값만 쓴다.
- 혼자 개발하므로 도구 설정과 학습 비용이 낮아야 한다.
- 포트폴리오 특성상 어떤 스택을 쓰는 면접관이 봐도 읽을 수 있어야 한다.
- 근무표 격자처럼 상태에 따라 색이 바뀌는 UI 가 많다.

## 선택지

1. **Tailwind CSS**
   - 유틸리티 클래스(`flex items-center px-4 text-sm`)로 마크업 안에서 스타일을 쓴다. 토큰은 `tailwind.config` 에 정의한다.
   - 장점: 신규 프로젝트에서 가장 많이 쓰이는 방식. CSS 파일 왕복이 없고, 안 쓰는 스타일이 빌드에서 제거된다. 디자인 토큰을 강제하기 좋다(설정에 없는 값은 쓰기 어렵다).
   - 단점: 클래스 문자열이 길어져 JSX 가 읽기 어렵다. `hover:`, `focus-visible:`, 반응형이 겹치면 한 요소에 클래스 15개가 붙는다. 스타일의 "의도"(이 여백은 왜 20px 인가)를 코드에 남기기 어렵다. 설정 파일과 PostCSS 설치가 필요하다.

2. **CSS Modules + CSS 변수 토큰** (Vite 기본 지원)
   - `Xxx.module.css` 에 일반 CSS 를 쓰면 클래스명이 파일별로 격리된다. 토큰은 `:root` 의 CSS 변수.
   - 장점: 추가 설치 없음. 그냥 CSS 라서 누구나 읽는다. 선택자 하나에 주석을 달아 의도를 남길 수 있다. CSS 변수라 특정 범위에서 토큰을 덮어쓰는 것(예: 한 화면만 색 반전)이 자연스럽다. 빌드 시 정적 CSS 로 나와 런타임 비용이 없다.
   - 단점: 토큰 강제가 약하다. 변수 대신 hex 를 직접 쓰는 걸 막는 장치가 없어서 규율에 의존한다. 클래스명을 지어야 한다. 파일 수가 두 배가 된다.

3. **styled-components / Emotion (런타임 CSS-in-JS)**
   - 장점: 컴포넌트와 스타일이 한 파일. props 로 스타일 분기가 쉽다.
   - 단점: 브라우저에서 JS 가 CSS 를 생성해 런타임 비용이 있다. React Server Components 와 구조적으로 맞지 않아 생태계가 이탈 중이고, styled-components 는 2025 년 유지보수 모드 선언. 신규 프로젝트에서 택할 이유가 약하다.

4. **vanilla-extract / Panda CSS (제로 런타임 CSS-in-JS)**
   - 장점: TypeScript 로 스타일을 쓰면서 빌드 시 CSS 로 추출. 토큰이 타입으로 강제된다.
   - 단점: 설정과 학습 비용이 가장 높다. 혼자 하는 프로젝트 규모에 비해 과하다.

## 결정

**2번 CSS Modules + CSS 변수 토큰.**

Tailwind 와 끝까지 저울질했다. 갈린 지점은 두 가지다.

- **읽는 사람**: 포트폴리오는 코드 리뷰를 받는 문서다. `className={styles.status}` 와 그 옆 CSS 의
  `/* 에러 자리 미리 확보: 메시지가 생겨도 버튼이 밀리지 않는다 */` 주석이,
  `className="min-h-5 -mt-1.5 text-[13px] text-red-600"` 보다 설계 의도를 더 잘 전달한다.
- **토큰 덮어쓰기**: 로그인 화면 배경 반전을 시험할 때 `.page { --ink-70: rgba(255,255,255,.72) }` 한 블록으로
  하위 컴포넌트(Button, Field)가 수정 없이 따라왔다. Tailwind 에서는 다크 variant 를 컴포넌트마다 붙여야 했다.

Tailwind 의 가장 큰 장점인 "토큰 강제" 는 규율로 대신한다. 규칙: **CSS 에 hex 값을 직접 쓰지 않는다. 색은 `var(--…)` 만.**

## 결과

- 컴포넌트 옆에 `Xxx.module.css` 를 둔다(co-location). `src/styles/` 에는 전역 토큰과 리셋만.
- Button, Field 는 색을 CSS 변수 훅(`--btn-primary-bg`, `--input-fg` 등)으로 받아 화면 단위 덮어쓰기가 가능하다.
- 토큰을 어기는 hex 직접 사용은 코드 리뷰(PR)에서 잡는다. 필요해지면 stylelint 규칙으로 자동화한다.
- 나중에 Tailwind 가 필요해지면(예: 팀 합류, 디자인 시스템 도입) CSS 변수 토큰을 `tailwind.config` 의 `theme.extend` 로 그대로 옮길 수 있어 전환 비용이 크지 않다.
- 면접 질문 "왜 Tailwind 안 썼어요?" 의 답은 이 문서다.
